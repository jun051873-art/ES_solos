# ES_solos · 10年磨一劍 P2.0.0 整合驗收版

此專案先完成店內自用系統的功能與流程驗收；正式雲端資料接替及 Google Play 單機版另行處理。

## 執行及重建

- GitHub Pages 的 `index.html` 是同一個固定入口。
- 程式、React 與 CSS 已打包在單一 HTML，沒有執行時 CDN 依賴。
- `app/source/` 是可修改原始碼；`app/build-tools/` 保留建置版本。
- 執行 `npm ci --prefix app/build-tools`，再 `node app/build-tools/build.cjs`，產出根目錄 `index.html`。
- 核心驗證：`node --test app/tests/core.test.mjs app/tests/wallet.test.mjs`。
- 瀏覽器脚本以本次工作環境的 Playwright 與 Chromium 路徑執行；移至其他電腦需調整執行檔與工作目錄。

## 現在可驗收

開單、服務折扣與數量、設計師／協助費試算、現金與其他付款、會員搜尋與歷史、人員薪酬、商品庫存、進貨及分次付款、店內耗用、支出、日期與月份報表、薪資草稿／已確認／已付、儲值收款與扣款、未用餘額退款、作廢回補、備份與還原。

虛業績＝折扣後服務收費（不含販賣）；實際業績＝虛業績－材料－協助費；抽成＝實際業績×設計師比例。百分比協助費按扣材料後、扣協助費前計算。

## 預付儲值口徑

- 入口：顧客 → 預付儲值。每筆儲值、扣款、退款、作廢都保留不可覆寫的流水。
- 儲值收款增加餘額與當期收款，但不增加消費業績。
- 開單可輸入儲值扣款額，再用一種其他付款方式補足；只有會員可扣儲值。
- 作廢消費會退回儲值、回補商品庫存，並登記其餘收款的退款；現實中的退款仍須櫃台執行。
- 退款限未用餘額；作廢儲值不允許造成負餘額。已退款流水不提供刪除或覆寫。
- 本版沒有贈送金、點數、到期失效、跨店錢包或預約訂金分攤。

## 報表口徑

- 消費業績與收款分開；營運頁顯示有效消費及其付款拆分，收支頁按收退款日期計入。
- 管理用損益＝消費收入－服務材料／販賣成本－變動人員報酬－已登記營運費用－已確認固定薪酬。
- 進貨付款、薪資付款、員工借支不重複計入已列成本／報酬。店內耗用留庫存流水，服務材料按帳單成本計算。
- 有底薪卻未確認薪資、非完整月份或歷史明細不足時，損益顯示「待核對」。不是稅務報表；稅費、折舊及未登記費用未涵蓋。

## 資料與雲端

目前用獨立本機測試資料，儲存鍵 `es_solos_p2_database`、格式版本 2。不是跨設備同步，也尚未接替正式店內雲端。

「系統 → 雲端銜接」只保存設定草稿；不啟動 Firebase、不登入、不讀寫原店資料。沒有自動連到 DEMO_STORE。不要輸入個人密碼或服務帳戶私鑰。

備份包含會員、帳單、庫存、薪資、儲值及收款流水。支援本專案 P1 格式升級；原作 Firestore 資料仍需正式對照移轉。瀏覽器被清除、無痕、換設備或路徑都可能失去本機入口，請下載外部備份。
